TRIBAL BATTLEFIELD ARCHITECTURE

部落战

我的职责游戏系统设计 / 战场架构 / 数据驱动内容 / 视觉反馈

  • Battlefield
  • Campaign
  • Energy Core

围绕能量核心争夺的战役地图与实时战场系统

战役摘要

部落战将战役推进与实时战场收在同一套游戏结构里：营地决定关卡入口与推进节奏，战场承载单位、投射物、状态与死亡反馈，能量核心则把双方的攻防目标集中到一个可被争夺、保护与逆转的战术焦点。项目采用组件、数据和预设拆分内容，使战役关卡、单位组合和战斗表现能够持续扩展。

统筹职责

游戏系统设计 / 战场架构 / 数据驱动内容 / 视觉反馈

战术工具

Godot · GDScript · Component System · Data-driven · Shader · Projectile · Campaign Map

第一卷

战场为何会
变得不可控？

敌情

战场项目会快速累积复杂度：单位、投射物、技能、状态、命中、死亡和出生特效彼此交织；若每个单位都各自处理规则，新增一种兵种或异常状态就会让战场逻辑变得不可控。与此同时，战役地图与单场战斗不能割裂，玩家需要感受到每一次推进都在改变整体战局。

×
阵法

以 battlefield 承载一场实时战斗的生命周期，以 camp / map 组织多阶段战役内容；单位通过 component 与 modifier 组合能力，投射物、命中、死亡、出生和状态反馈分拆为独立效果层。能量核心被设计为战场级目标，统一连接单位推进、阵地攻防与局势反馈；关卡、预设和测试数据则从运行逻辑中抽离，降低内容扩展成本。

第二卷 / 作战节点

让每一层职责守住自己的阵线

  1. 01

    战役营地与多关卡推进结构，连接地图层与即时战场层

  2. 02

    以能量核心作为可争夺的战场级目标，组织进攻、防守与局势逆转

  3. 03

    战场单位、投射物、命中、死亡、出生与状态效果分层管理

  4. 04

    component + modifier presets 组合单位能力，降低新兵种和技能的实现耦合

  5. 05

    map、model、datas 与全局系统分离，支持关卡内容和数值配置独立迭代

  6. 06

    shader 与 effect 模块提供弹道、护盾、命中、涟漪、尾迹等战斗可读性反馈

  7. 07

    camp001 至 camp005 的战役目录为不同地图、阶段与挑战提供内容组织基础

第三卷 / 六部阵型

战役不是一团脚本，
而是一支有编制的军队。

DIVISION 01

Campaign / Camp

以营地和分关卡组织战役推进、挑战节奏与地图入口

DIVISION 02

Battlefield

管理一场战斗中的单位出生、推进、胜负与战场级事件

DIVISION 03

Energy Core

作为双方争夺的核心目标，连接攻防节奏与局势反馈

DIVISION 04

Unit Composition

component 与 modifier 预设组合单位行为、属性和状态变化

DIVISION 05

Projectile / Hit

投射物、命中、尾迹与伤害反馈独立于具体单位实现

DIVISION 06

Effect / Shader

出生、死亡、状态、涟漪与基础特效强化大规模战斗可读性

后续演进 · 以下为路线图，具体阶段以项目说明为准。

第四卷 / 行军路线

从一场交锋，推进到一场战役。

1
MVP

先让一场围绕核心目标的部落交锋完整成立

  • 双方营地与基础战场循环
  • 单位生成、推进、投射物与命中
  • 能量核心攻防与胜负结算
  • 基础出生、死亡和状态反馈
2
V1

让战役内容和战术组合持续生长

  • 多营地、多地图与阶段化战役
  • modifier 预设驱动的兵种与技能组合
  • 更丰富的状态、弹道与 shader 表现
  • 数据测试与战场平衡调优工具链
第五卷

战场军规

令
  1. 其 1

    能量核心不是装饰物，而是将单位推进、营地防守和胜负目标统一起来的战场规则中心。

  2. 其 2

    单位规则保持组件化，效果表现保持独立，避免一个兵种脚本承担战斗系统的全部复杂度。

  3. 其 3

    战场必须可读：投射物轨迹、命中、状态、出生和死亡都应帮助玩家理解局势。

  4. 其 4

    战役目录与数据配置是内容生产能力的一部分，关卡扩展不应依赖反复改动核心战斗代码。
