ARCHITECTURE NOTE / 001

breconn 是一套目前约 2 万行代码、基于 Asio 的网络库。上层只使用简洁、统一的 Channel 接口，不需要直接处理不同传输协议的连接、收发与生命周期差异；底层目前提供 TCP、UDP、KCP，以及 UDP 组播与广播能力，QUIC 作为后续传输能力规划。协议层已经覆盖 HTTP 与 WebSocket，mDNS 被拆成解耦的服务发现模块，并通过插件机制为 RTP 等新协议保留动态扩展入口。

PROBLEM / A

协议差异，不应该泄漏到业务。

TCP、UDP 与 KCP 在连接语义、可靠性、消息边界和生命周期上差异明显，如果业务直接依赖各自的 Socket API，每增加一种传输方式都会把分支扩散到上层。组播、广播与 mDNS 又同时涉及网卡选择、地址管理和服务发现状态；如果与 UDP 或业务代码强绑定，协议层和发现服务便无法独立测试、替换与复用。

DECISION / B

把变化隔离在 Channel 的另一侧。

以 Asio 承担异步 I/O 与事件循环，在传输实现之上建立统一 Channel 抽象，把打开、关闭、读写、错误和状态变化收敛为稳定接口。UDP 后端提供组播组管理与广播收发，mDNS 则作为独立服务使用标准 Channel 能力完成发现与公告。HTTP 与 WebSocket 作为协议层运行在 Channel 之上，并通过协议插件注册与装配机制扩展新的解析、封装和会话逻辑。
